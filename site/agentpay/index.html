Live on Kadena mainnet · pilot

AI agents that pay in KDA, within limits the chain enforces

Kadena AgentPay AI lets an AI agent pay for data and compute on its own. The owner sets the spending limits once, and a Pact contract on Kadena applies them to every payment. The agent cannot overspend, even if the agent or its server is compromised.

The owner sets the limitsA maximum per payment, a maximum per day, a pause switch, and an optional list of approved sellers.
The agent holds no fundsThe KDA stays in a vault. The agent has only a signing key, which can make payments inside the limits and nothing else.
It follows x402Payments follow x402, the open standard for payments over HTTP, and are tested with the official x402 JavaScript libraries.

The live service is at agentpay.kadena.ws. Agents pay per call in KDA through this contract, or in USDC on Base or Polygon.

How one purchase works

An agent asks a seller for something, such as a data report. The seller answers with a price. The agent pays, and the seller hands over the data once the payment is in a block.

  1. PriceThe seller answers "402 Payment Required" with the price in KDA and a one-time payment id.
  2. SignatureThe agent signs one payment for exactly those terms. It needs no KDA of its own; the facilitator pays the gas.
  3. LimitsThe contract on Kadena applies the owner's limits. A payment outside them is refused and costs nothing.
  4. DeliveryThe seller returns the data with a receipt once the payment is in a block. On mainnet every purchase waits for the block.

What the chain enforces

These rules live in the Pact contract, not in the agent's software, so they hold even when the agent is fooled or its server is taken over.

Per-payment limit
The most KDA one payment may move.
Daily limit
The most KDA all payments may move in one day.
Pause switch
The owner can stop all payments at once, and resume later.
Approved sellers
Optional. When on, the agent can pay only accounts the owner has approved.
One-time payment ids
Each payment id works once, so a payment cannot be replayed.
No withdrawals by the agent
Only the owner can withdraw from the vault, change limits or replace the agent key.

Tested with the official x402 libraries

The official JavaScript libraries from the x402 Foundation (version 2.31.0) were run against AgentPay, and all 16 checks pass:

  • The official client read our price answer, paid, and decoded our receipt.
  • The official facilitator client used our facilitator to check and settle a payment.
  • A seller built with the official middleware was paid by our agent.
  • The official client and the official seller worked together, with our facilitator between them.

The libraries have no Kadena support of their own; two small plug-ins add it. This test used a stand-in for the chain, not the devnet, and covers the JavaScript libraries only. Kadena is not yet a listed x402 network.

Why build this on Kadena

Signatures with a stated purpose

On Kadena a signature can be limited to one named action. The agent signs "pay this seller this amount for this payment id" and nothing wider.

Contracts anyone can read

Pact contracts are stored on the chain as readable code, so an owner, a seller or another AI can read the exact rules that guard the vault.

The agent needs no gas

A separate account pays the transaction fee, with a signature limited to paying gas. The agent never has to hold or manage KDA.

Small payments stay small

Kadena's transfer fees are low enough for payments of a fraction of a cent. See the daily fee comparison.

Questions

Can I use it today?

Yes, as a pilot on Kadena mainnet. An owner can set up an allowance on the owner page, and an agent can buy the Kadena Nexus tools with it. The contract has had AI-assisted reviews but no human audit yet, so keep the amounts small. To practice with test KDA, use the devnet demo.

What is x402?

An open standard that lets software pay for a web request. A server answers "402 Payment Required" with a price, and the client pays and asks again. It was created by Coinbase and is now governed by the x402 Foundation at the Linux Foundation. Read more at x402.org.

What happens if the agent is tricked into paying?

The damage is capped by the owner's limits. With the approved-sellers list on, a tricked agent still cannot pay an account the owner did not approve. The owner can pause the allowance at any time.

Is this a trading bot?

No. It does not trade or hold funds for anyone. It is a way for an agent to pay for services, with the owner's KDA staying in a vault the owner controls.
